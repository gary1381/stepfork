# Stepfork v0.2.0 - Failure Minimization and Fork-at-Step Debugging

This release adds automatic failure minimization and fork-at-step debugging,
with an optional override system. Existing `.sftrace` bundles remain
compatible; frozen replay remains the default.

## Changes

- **Failure minimization** via `stepfork minimize`: dependency-aware delta
  debugging finds the smallest trace that still reproduces the original
  failure, preserving parent-child event relationships and structural
  integrity. Detects exception-based, replay-divergence, and output-mismatch
  failures, and handles timeouts and nondeterminism. See
  [minimize documentation](https://utsab345.github.io/stepfork/minimize/).
- **Fork-at-step** via `stepfork fork`: create new traces at specific
  execution points (`--at-step N` or `--at-event ID`) while preserving all
  valid history before the fork point. Provenance is tracked with `ForkInfo`.
  Overrides of tool results and LLM responses are available through the Python
  API (`OverrideSpec`). See
  [fork documentation](https://utsab345.github.io/stepfork/fork/).

### Limitations

- Minimization requires replay to fail consistently; highly nondeterministic
  failures may not minimize reliably.
- Delta debugging uses dependency-preserving search; very large traces (1000+
  events) may require many replay attempts.
- Timeout handling uses `SIGALRM` on Unix; Windows support is limited.
- Fork overrides are Python-API only and can modify outputs
  (`tool_result`, `llm_response`), not inputs.
- Fork creates modified traces but does not continue execution from the fork
  point; replay must be invoked separately.

## Installation

```bash
pip install stepfork
```

Requires Python 3.11, 3.12, or 3.13.
